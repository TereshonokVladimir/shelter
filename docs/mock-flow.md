# Solo mock flow (dev / QA)

Моки нужны, чтобы один ведущий прошёл весь цикл без живых игроков. На проде их легко выключить или вырезать.

## Что есть в seed

| Контент | Кол-во | Для max 12 игроков |
|---|---:|---|
| Катастрофы | 10 | ок |
| Убежища | 10 | ок |
| Характеристики × 8 категорий | 20 каждая (160) | ок (≥12 на категорию) |

Seed досыпает недостающие disasters/bunkers/категории, если БД частичная.

## Включение моков

API: `ENABLE_MOCK_BOTS`  
- `true` / не задано при `NODE_ENV !== production` → моки **вкл**  
- `false` / `NODE_ENV=production` (по умолчанию в prod compose) → моки **выкл**

Флаг отдаётся в snapshot как `mocks_enabled` — UI прячет кнопки ботов сам.

## Код моков (удалить на проде при желании)

- `api/src/game/mocks/` — вся логика ботов  
- Роуты в `game.controller.ts`: `mock-players`, `bots/act`  
- UI: кнопки «Добавить ботов» / `HostBotsButton`

## Happy path (ведущий один)

1. Создать комнату (discussion 30–60 сек удобнее для теста).  
2. Лобби → **Добавить ботов** (≥1 раз, минимум 4 игрока).  
3. **Начать игру**.  
4. Раскрытие: открыть свою характеристику → **Боты раскрывают** → **Дальше: обсуждение**.  
5. Обсуждение: **Начать голосование** (боты обсуждение не «играют»).  
6. Голосование: выбрать кандидата → подтвердить → **Боты голосуют** → **Показать результат**.  
7. Результат: **Следующий раунд** (или переголосование при ничьей) / **Завершить игру**.  
8. Повторять 4–7, пока не наберётся вместимость убежища → финал.

`vote_progress` в snapshot показывает `cast/total` без раскрытия чужих целей — иначе кнопка результата не включалась после ботов.

## Выключить на проде

```env
ENABLE_MOCK_BOTS=false
NODE_ENV=production
```

Или удалить папку `api/src/game/mocks/` и два mock-роута в контроллере.
